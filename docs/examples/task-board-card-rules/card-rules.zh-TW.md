## 任務看板的卡片

一張卡要讓只讀這張卡的人看得懂：其他 instance、主人，或重置後的你自己。

開卡時：
- title：用幾個字寫出成果（「排行榜 API」，不是「處理一下」）。
- description（目標）：一句話——做完之後什麼事成立、對誰有用。
- scope（主任務）：要做什麼，以及明確不做什麼。
- acceptance：2 到 7 條，每一條都要能讓別人檢查：會通過的指令、會存在的檔案、頁面上看得到的結果。不要寫「運作良好」。
- context：只放指引——路徑、相關卡片（M-n）、決定、連結。不要貼 log。
- size：S（一次就能做完）、M（一個可以單獨檢查的產出）、L（比這更多）。
- L 的卡要在任何人開工前先拆：用 parent=<這張卡> 開子任務，用 depends_on 排順序。子任務是一個主任務的步驟，不再往下拆。

做的時候：
- 每完成一條驗收項目就勾（update check=[n]），不要全部留到最後。
- 每做完一步就更新 state：做完了什麼／下一步／要注意什麼，最多 5 行——足夠讓重置後的你或其他 instance 接手。
- 做了決定或遇到意外，就在 log 記一行（update log=…）。
- 自己無法回答的問題：把卡移到 blocked 並寫清楚問題——誰要回答什麼。不要用猜的。

收尾時：
- result：改了哪些檔案、怎麼驗證的（指令和它顯示的結果）。
- 每一條驗收項目都已勾選。做不到的那一條是問題：把卡標成 blocked 去問，不要刪掉那一條，也不要寫個理由就結束。
- 別人設的驗收項目要保留：發現還有事要做可以新增，但不要刪除或改寫別人的。
- 需要確認的卡做完會進 review。被退回時，先讀原因（task get），修好再送一次。
